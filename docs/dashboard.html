Dashboard Source and Site Architecture

Scoring Specification: 1.0  |  Specification Issue: GitHub Issue #10  |  Specification Doc: docs/qc-trimming-recommendation-system-specification.md

This document describes the maintainable source files, configuration, and generated site responsibilities for the interactive QC-trimming recommendation dashboard and Methods & robustness documentation.

1. Responsibilities: Source vs. Generated Artifacts

Human-Editable Source (Version-Controlled on Default Branch)

Future contributors and maintainers must edit only these source files: - tool_weighting.qmd: The primary Quarto/Shinylive human-editable dashboard source document. Contains page markup, flow regions, UI components, and client-side reactive logic. - methods_and_robustness.qmd: The Quarto Methods & robustness reference page documenting equations, assumptions, policy anchors, provenance, and repository-only stability results. - config/dashboard_config.yaml: The configuration for repository provenance, evidence location, pinned commit/content hashes, and site base URLs. Editing this file configures provenance and repo renames without altering scoring equations or application logic. - src/qc_scoring/: The pure Python canonical scoring library (models, validation, criteria value functions, preferences, gates, warnings, and ranking). - _quarto.yml: The Quarto site configuration and navigation bar links. - assets/data/assembly_metrics.csv: Bundled and pinned benchmark metrics CSV (884 observations at commit 4d6b8cb1d482e5066f9ca575ebd3b67af4a32562).

Generated Artifacts (Never Edit Directly)

  • _site/: Output directory generated by quarto render. Contains compiled HTML, bundled JS/CSS, and WebAssembly runtime files.
  • Compiled files like _site/tool_weighting.html are transient publication targets, NOT sources of truth. They must not be edited by hand.

2. Pinned Evidence and Offline Execution

The dashboard does not read from the moving HEAD of a branch. Benchmark evidence is pinned to commit 4d6b8cb1d482e5066f9ca575ebd3b67af4a32562 and bundled directly with the application source, allowing full offline rendering and execution without network requests.

3. One-Page Flow Regions

The dashboard UI is structured into five sequential, keyboard-accessible flow regions: 1. Scenario Selection (region-scenario): Basecalling model (hac or sup) and sequencing depth (20x or 100x). Selections start unset. 2. Priorities & Weights (region-priorities): Presets (Community-balanced, Complete-replicon-recovery, Sequence-accurate-assembly, Custom), percentage sliders totaling 100%, and optional eligibility gates. 3. Recommendation Shortlist (region-shortlist): Top 5 eligible recommendations ordered by preference-alignment score, button to reveal all 17, and collapsed container for excluded alternatives with reasons. 4. Selected Combination Detail (region-detail): Detailed breakdown of raw metrics, per-isolate diagnostics, and warnings. 5. Concise Methodology & Provenance (region-methodology): Value function definitions, aggregation rules, link to Methods & robustness, and configured repository provenance metadata.

4. Verification & Build Commands

  • Run Unit Tests & Smoke Checks:

    pytest

  • Typecheck Library:

    mypy src/qc_scoring

  • Render Dashboard:

    quarto render tool_weighting.qmd

  • Preview Site Locally:

    quarto preview
